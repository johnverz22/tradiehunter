# TradieHunter Web Design Guide v1 (Trust Navy + Gold, admin)

Scope: the React admin dashboard (`web/`). Light and dark. The homeowner and tradie experiences are mobile only (see `../mobile/`).

Single source of truth: `tokens/tokens.json` (web layer) on top of `../mobile/tokens/tokens.json` (master), `css/kit.css` (components) and `ast/screens.mjs` (screens). Everything else is generated by `node tools/build.mjs`.

## 1. Principles

1. **Same brand, denser room.** Web inherits the mobile palette, fonts, space scale and radii. It changes density, not identity: 40 px controls, 14 px table text, tighter radii roles.
2. **One gold action per view or dialog.** Gold (`btn-accent`) is the commit action: Verify tradie, Verify payment, Resolve dispute, Save changes, Sign in. Navy `btn-primary` is for other filled actions (row actions such as Verify in a queue). Danger red is for destructive actions only.
3. **Money is exact.** Amounts are NZD, labelled incl. GST where shown, right-aligned with tabular figures. Missing data is shown as unavailable (`Not provided`, `—`), never as zero.
4. **Status is never colour alone.** Every badge carries its status text; steppers carry check and cross icons; banners carry an icon and a title.
5. **Queues are the product.** Staff work down lists. Tables are scannable (56 px rows, sticky header), actions sit at the row end, and the page owns one primary action.
6. **Dark is first-class.** Dark is a token swap. Components never branch on theme; shadows are tokens (`none` in dark, with the border doing the work).
7. **Quiet chrome, one signature.** Navy sidebar with a gold current-page marker is the one memorable element. Everything else is restrained.

## 2. Relationship to mobile

| Aspect | Inherited from mobile | Web decision |
|---|---|---|
| Colour | Every colour token, light and dark, by `extends` | Adds `lineStrong`, `focus`, `onDanger`, sidebar set, `scrim`. CSS names: `text`→`ink`, `textSoft`→`ink-soft`, `textBrand`→`ink-brand`, `tintBrand`→`brand-tint`, `accentText`→`accent-ink`, `avTradie`→`avatar` |
| Fonts | Lexend (display) + Source Sans 3 (body) | Adds a system monospace for ids and references |
| Space | 4pt scale `s1`–`s9` | Adds 64 and 80. CSS `--sp-N` = px / 4 so it matches Tailwind |
| Radii | `small 10`, `control 16`, `card 20`, `hero 28`, `pill` | Roles shifted one step tighter: control 10, card 16, panel 20, hero 28 (login aside, bottom sheets) |
| Motion | 150 / 220 / 320 ms | Same. Reduced motion collapses all animation |
| Elevation | Soft two-layer card shadow in light, border only in dark | Same, plus `pop` and `modal` |
| Gold rule | One gold CTA per screen | One per view or dialog |
| Feedback | `THNotice` tones | Banners (persistent) and toasts (success and info only), see COMPONENTS |
| Type scale | display 28, h1 24, h2 20, title 16, body 15, meta 13 | Same h1, h2, title, body and meta. Adds `bodySm` 14 (tables), `stat` 28, `label` 12 sentence case (no all-caps on web), `mono` 13 |

Do not edit colour in `web/tokens/tokens.json`: change `../mobile/tokens/tokens.json` and rebuild both. The web build fails if a `=path` reference no longer exists in the mobile master.

## 3. Colour

See [COLOUR.md](COLOUR.md). Use `var(--ink)` or the Tailwind utilities generated in `tokens/theme.css` (`bg-surface`, `text-ink-soft`, `border-line`). Never hardcode hex; `kit.css` is linted for raw colour.

## 4. Typography

See [TYPOGRAPHY.md](TYPOGRAPHY.md). Page title `h1` 24, section `h2` 20, card title `title` 16, body 15, table `bodySm` 14, captions `meta` 13. Line length for prose stays under 75 characters.

## 5. Space, shape, size

Use `--sp-*`, `--r-*`, `--sz-*`. Controls are 32 / 40 / 48 px (`controlSm`, `control`, `controlLg`); on coarse pointers anything under 44 px grows to 44. Page gutter 24 (16 on phones), content max 1280. Table row 56, compact 44, header 44.

## 6. Layout

| Width | Shell |
|---|---|
| ≥ 1024 | Full sidebar (240), top bar (56), content max 1280 |
| 640–1023 | Icon rail (64). Labels are visually hidden but remain in the accessibility tree |
| < 640 | Sidebar becomes a drawer opened from the top bar menu button. Dialogs become bottom sheets. Tables scroll inside their container (min 640 px). Steppers go vertical |

Detail pages use a `side` grid (2fr / 1fr) that stacks below 1024. Stat rows are 4 columns, then 2, then 1.

## 7. Components

See [COMPONENTS.md](COMPONENTS.md) for the specification of each component (purpose, anatomy, variants, states, accessibility, tokens). The runnable reference is `mockups/system.html`.

## 8. Patterns

- **Queue page** (credentials, payments, payouts, refunds): page header, optional filter bar, table with row actions, pagination. No gold on the page unless there is a page-level commit.
- **Detail page**: breadcrumb, header with status badge and page actions (gold last), job stepper where relevant, `side` grid of cards. Money in a `dl` with the total on a `total` row.
- **Confirm dialog**: the dialog repeats the facts being acted on (job, person, amount, reference). Footer is Cancel (secondary) then the commit button (gold, or danger when destructive). Initial focus goes to Cancel for destructive dialogs.
- **Forms**: label above, help below, errors say what is wrong and how to fix it. Required is the default; mark optional fields.
- **Feedback**: banners are inline, flat and persistent: a small tone icon tile carries the meaning, with a hairline border only for warn and danger. There are no side stripes and no tinted fills. Toasts are inverse snackbars (ink background) for short confirmations. Errors and warnings are never toast-only and never auto-dismiss.
- **Empty and error states**: say what is empty and what to do next; errors give a Retry.

## 9. Accessibility

- Contrast gate in the build: 47 text pairs at 5.0:1 (AA is 4.5:1, plus margin) and 16 non-text pairs at 3:1 per theme (`tokens/contrast-report.txt`). Form control borders use `line-strong`, not `line`, to meet SC 1.4.11.
- Visible focus: 2 px `--focus` outline, 2 px offset, on every interactive element. Never `outline: none` without a replacement.
- Keyboard: dialogs trap focus, close on Esc and return focus to their trigger; menus use arrow keys; table sort buttons are real buttons with `aria-sort` on the header.
- Targets: 44 px minimum on coarse pointers.
- Icon-only buttons need `aria-label`. Rail items keep their text in the DOM.
- `role="alert"` for danger banners, `role="status"` for the rest. Stepper marks the current step with `aria-current="step"`.
- `prefers-reduced-motion` removes animation; `forced-colors` gives badges a border.
- Page language and title are set; the page has one `h1` (the page header).

## 10. Integration into `web/`

`web/src` runs this system. `web/src/theme/tokens.css`, `theme.css` and `components.css` are **copies** of `tokens/tokens.css`, `tokens/theme.css` and `css/kit.css`, and `web/public/fonts/` is a copy of `fonts/`. Never edit the copies. To change the design, change it here, run `node tools/build.mjs`, then from `web/` run `npm run design:sync`.

Checks (all run in CI):

- `node docs/design/web/tools/build.mjs --check` for the design system itself.
- `npm run design:check` in `web/` fails if the copies differ from this folder.
- `npm run design:legacy` in `web/` fails on any use of the retired v1.7 names listed below.

Rules for app code: tokens and kit classes only; app-level CSS in `web/src/index.css` is for what the kit lacks (see §12) and uses tokens only; shared components in `web/src/components` keep the names and props in COMPONENTS.md. Verify a page with `npm run lint`, `npm run build`, its Playwright spec and `scripts/web/render-probe.py`, and compare it with `mockups/index.html`.

## 11. Workflow and gates

```bash
node tools/build.mjs          # regenerate tokens, Tailwind theme, resolved JSON, AST JSON and mockups
node tools/build.mjs --check  # CI gate
```

The gate fails on: contrast regression, an unresolved `=path` or `@alias`, a raw colour or an undefined `var(--x)` in `kit.css`, an unknown AST node or icon, a gap value outside the space scale, a screen missing from the gallery, a colour missing from `system.html`, or stale generated files.

**Change a colour:** edit `../mobile/tokens/tokens.json`, then run both builds. **Change a web-only role:** edit `tokens/tokens.json`. **Change a component:** edit `css/kit.css` and, if markup changes, the emitter `H()` in `tools/build.mjs`. **Add a screen:** edit `ast/screens.mjs`, add it to a gallery section in `tools/build.mjs`, rebuild, review `mockups/index.html`. **Add a node type:** add it to `ast/dsl.mjs`, `KNOWN` and `H()` in `tools/build.mjs`.

## 12. Assumptions, decisions and gaps

- **Decided: the `--hue` white-label knob is dropped.** Web inherits the fixed mobile palette. If per-tenant branding returns, it should be a token override layer for `brand`, `accent` and the hero/sidebar set, with the contrast gate run per tenant.
- **Decided: fonts are self-hosted** (woff2 in `fonts/`, no CDN), including latin-ext for Māori macrons. See TYPOGRAPHY.md.
- Sample names, ids, counts and amounts in the mockups are illustrative. The commission figure follows the v1.7 spec (labour only, configurable).
- The settings screen is a form-pattern demonstration, not a statement of which settings exist.
- Icons in the mockups are simplified strokes; the app uses `lucide-react` (names listed in `tools/build.mjs` `ICONS`).
- Refunds, payout batches, batch detail and credential review dialogs reuse the queue and dialog patterns and have no separate frame.
- Not designed: charts, bulk selection bars, date-range pickers, tooltips and popovers beyond the menu, print styles, high-contrast beyond `forced-colors`, a tenant-branded login.
- The mockup CSS and markup were checked in a headless browser at 1280, 820 and 390 px in light and dark. The React admin was migrated onto this system with scripted gates only (lint, build, sync, legacy guard, this gate); the side-by-side frame comparison, keyboard and screen-reader walks and the Playwright run are manual.
- App-level additions in `web/src/index.css` for what the kit lacks (candidates for the kit): sign-in layout fixes and brand-on-card, skip link, sidebar footer buttons, receipt image, photo grid and tiles, long-text block, scrolling region, phone action bar and its "More" disclosure, evidence item, code block, section heading, link-styled button.
- Differences between frames and the app that are data or behaviour, kept as the app has them: dispute outcome buttons (the frame has a select), no money card on job detail, no credentials table on user detail, no payment-count cards on the dashboard.
- The phone card list in `DataTable` (under 640 px) is an app pattern the kit does not define; the `<details>` "More" menus have no arrow-key roving.
