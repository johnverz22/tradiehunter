# TradieHunter Design Guide v2: Trust Navy + Gold

Mobile only. Light and dark. Built from the v1.7 job flow (post without a price, choose a tradie, request, price adjustments, approve and pay at completion) plus the earlier entry, onboarding, project-quote and dispute flows.

Single source of truth: `tokens/tokens.json` and `ast/screens.mjs`. Everything else (Dart tokens, CSS, Flutter screens, HTML mockups) is generated by `node tools/build.mjs`.

## 1. Principles

1. **Trust first.** Navy carries structure. Verified and Insured badges are always visible on a tradie. Money is always labelled `incl. GST` and NZD.
2. **One gold action per screen.** Gold (`accent`) is the single primary CTA: Choose a tradie, Request this tradie, Accept job, Approve, Upload receipt. Navy `primary` is for secondary-importance filled actions (Message, Approve an extra cost, Sign in).
3. **Money is the loudest thing on screen.** Final amounts use `moneyLg` on a hero card.
4. **Same system, two points of view.** Homeowner and tradie screens share every component. Differences are content and the dock (homeowner has the in-line Post job slot, tradie does not).
5. **Long screens, not cramped screens.** Screens scroll. Primary actions live in the sticky bar, never below the fold.
6. **Dark is a first-class theme**, not an inversion. Brand lightens to periwinkle, gold lightens, surfaces step up in blue-black.

**Contrast is enforced by the build.** 19 text/background pairs per theme must reach 4.5:1 (WCAG AA) or the build fails. See `tokens/contrast-report.txt`. Two earlier values failed and were corrected (`success` light, `heroGold`).

Rules:
- White text on gold works in light mode only. In dark mode gold takes `onAccent` (near-black). Always pair `accent` with `onAccent`, never with a literal.
- Use `accentText`, not `accent`, when gold is the colour of text.
- Status colour is never the only signal. Badges carry text, timelines carry icons.

## 4. Space, shape, size

4pt scale: `s1` 4, `s1_5` 6, `s2` 8, `s2_5` 10, `s3` 12, `s3_5` 14, `s4` 16, `s5` 20, `s6` 24, `s7` 32.
Radii: control 16, tile 18, card 20, hero 28, sheet 32, pill 999.
Screen gutter 20. Button 54 (sm 44). Input 56. Tap target never below 44. Dock 72 (Post job tile 48, glyph 28, content cap 560, label clamp 1.3×), FAB 56.
Editable field labels use the small-caps uppercase treatment shown in the mockups; field labels and values sit inside the same outlined surface.
Elevation: cards use a two-layer soft shadow in light mode and a 1px border only in dark mode. Hero cards use the gradient and a gold glow circle. No other shadows.
Motion: 150 / 220 / 320 ms (`THDurations.fast/base/slow`). Use for toggles, dots, progress.

## 5. Signature elements

- **Hero card** (`hero`): navy gradient, gold eyebrow label, one large figure. Used for the attention item, amount to pay, offer countdown, net earnings.
- **Bottom dock** with an in-line gold **Post job** slot (Semantics label `New request`). The tile carries a custom glyph: a hunter's crosshair with a plus at its centre (ring, four ticks, plus). It replaces the generic `+`. In Flutter it is `THHuntGlyph`, not an icon font entry. The bar is full-bleed (opaque, flush with the bottom edge, 1 px `line` top hairline, no radius or shadow). Full spec: COMPONENTS.md.

  > **Deviation from the original mockups (2026-11-20).** The first mockups drew a floating, rounded, shadowed pill inset 14 px from the sides and 16 px from the bottom, with a raised 56 px gold FAB that broke out of it. Content showed through the gap around the pill, so it was replaced by the full-bleed bar above. `mockups/index.html` is regenerated from the AST. `mockups/png/*` still show the old pill until `mockup-shots.mjs` is re-run (needs network for fonts).
- **Sticky action bar** (glass): decline and accept pairs, or a single CTA. Always above the home indicator.
- **Progress segments** (`prog`): five segments for the job lifecycle (Posted, Requested, Booked, In progress, Complete). Green done, gold current.
- **Timeline** (`timeline`): vertical, for what-happens-next and job history.

## 7. Screen inventory (30)

Each screen has its Flutter class in `flutter/screens/<id>_screen.dart` and its route in `thScreenRoutes`.

**Entry and shared (8):** `splash`, `onboarding`, `role_select`, `sign_in`, `verify_otp`, `chat`, `notifications`, `profile`.

**Homeowner (15):** `ho_home`, `ho_post_quick`, `ho_post_project`, `ho_quotes`, `ho_choose_tradie`, `ho_tradie_profile`, `ho_request_sent`, `ho_job_booked`, `ho_extra_cost`, `ho_review_completion`, `ho_payment`, `ho_payment_status`, `ho_review`, `ho_dispute`, `ho_jobs`.

> **Quote screens:** `ho_quotes` shows compact cards; "View quote" opens a bottom-sheet detail in the app that has no mockup frame yet (`ho_quote_detail` is to be added, plan 10 Q3.1). The tradie quote builder is a bottom sheet by design (plan 10 D3) and has no `tr_quote` frame.

**Tradie (7):** `tr_home`, `tr_lead` (full-screen request with every detail), `tr_job`, `tr_extra_cost`, `tr_complete`, `tr_earnings`, `tr_onboarding`.

The **tradie lead** is a full screen, not a card. It shows the offer countdown, job title, service, timing, full description, photos, area and distance (exact address only after accepting), estimated hours, job type, homeowner name and rating, the locked rate with commission and what the tradie keeps, a what-happens-next timeline, and sticky Decline and Accept.

## 9. Accessibility

- Contrast gate in the build (AA, 4.5:1).
- Tap targets 44 minimum (buttons 54 or 44, dock slots a fifth or quarter of the width and at least 48 high, icon buttons 44).
- Every icon button needs `semanticLabel`. Generated code sets it from the icon name; replace with a real label ("Notifications").
- `THSwitch` exposes `toggled`. `THDock` items expose `selected`.
- Never convey state by colour alone.
- Respect text scaling: layouts use `Expanded` and wrapping, no fixed text heights.

## 10. Flutter integration

Requires Flutter 3.27 or newer (`Row.spacing`, `Color.withValues`).

1. Copy `tokens/design_tokens.dart` to `mobile/lib/theme/design_tokens.dart` (replaces v1.6.2). `Space`, `Radii`, `Sizes`, `THType`, `THColors` keep their names. `THColors` gains fields (`surfaceAlt`, tints, hero and glass) and loses none of: `paper surface text textSoft textBrand brand onBrand accent accentText line tintBrand track danger success avTradie onAvTradie`. The old `outdoor` variant is not part of v2.
2. Copy `flutter/th_widgets.dart` next to it, and `flutter/screens/` to `mobile/lib/views/design_v2/`. Fix the two relative imports if you place them elsewhere.
3. Add the fonts to `pubspec.yaml`.
4. Wire the theme:
   ```dart
   MaterialApp(theme: THTheme.light, darkTheme: THTheme.dark, themeMode: ThemeMode.system, ...)
   ```
5. Preview all screens while building: `thScreenBuilders['tr_lead']!(context)` from a debug-only gallery route.
6. Replace sample data. The generated screens are layout and copy only. Move each into your view and bind data, keeping the widget tree. Example: replace `THText('Leaking kitchen tap', ...)` with `THText(job.title, ...)`.
7. Run `dart format .` and `flutter analyze`. The generator emits compact formatting.

Mapping from the v1.6.2 widgets: `FixoPrimaryButton` to `THButton(kind: accent)` for the one gold CTA or `kind: primary` otherwise, `FixoAppBar` to `THAppBar`, `THHeroBand` to `THHero`, `THStatusStrip` to `THBadge` or `THProgress`.

## 11. AST workflow

```bash
node tools/build.mjs          # regenerate tokens, Flutter, HTML
node tools/build.mjs --check  # CI: fail on stale outputs, contrast, unknown nodes or icons
```

**Change a screen:** edit `ast/screens.mjs`, rebuild, review `mockups/index.html`, commit the generated files.
**Change a colour or size:** edit `tokens/tokens.json`, rebuild. The contrast gate tells you if it broke accessibility.
**Add a node type:** add the builder in `ast/dsl.mjs`, add it to `KNOWN` and to the `html()` and `dart()` switches in `tools/build.mjs`, and add the widget to `flutter/th_widgets.dart`. A missing case fails the build with `unknown node`.
**Add an icon:** add an entry to `ICONS` in `build.mjs` with an SVG path for the mockup and a Material rounded name for Flutter.

Node shape (also in `ast/screens.ast.json`):

```json
{ "t": "btn", "v": "Accept job", "k": "accent", "x": true }
{ "t": "card", "tone": "accent", "pad": 16, "c": [ { "t": "kv", "l": "Your rate", "v": "$85/hr", "b": true } ] }
```

Screen shape: `{ id, title, route, role, bar?, nav?, dock?, sticky?, bg?, body: [nodes] }`.

## 12. Assumptions and gaps

- Sample copy, names, amounts, the bank account and the 10% commission are illustrative. The v1.7 spec makes commission labour-only and configurable.
- Generated Dart was checked for bracket balance and against the widget API by reading, but **not compiled** (no Flutter SDK in the build environment). Run `flutter analyze` first.
- No outdoor or high-contrast variant, no tablet layouts.
- Splash, onboarding illustration and the map are placeholders for real assets.
- Not covered: admin and staff screens, push-permission prompts, empty and error states, skeleton loading.
