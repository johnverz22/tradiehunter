## Fixes applied during the run (all real bugs)

### Backend
- `backend/Program.cs` — `__Host-fixo-admin` cookie with `Secure` is **rejected outright by browsers over http**, making the whole admin panel unusable on localhost (every admin mutation 401→login loop). Dev now uses `fixo-admin` + `SameAsRequest`; production keeps the hardened cookie.
- `backend/Controllers/AdminController.cs` — `CurrentUserId` only read the JWT `sub` claim; cookie-auth requests carry `ClaimTypes.NameIdentifier`, so **every admin POST 500'd** ("User ID claim missing"). Added fallback.
- DB: applied **6 pending EF migrations**. `SeedNZServices` collided with `ProfileService`'s runtime auto-seed (`ProfileService.cs:302` inserts "Plumber"/"Electrician"… over the same IDs the migration wants) — deleted the stale rows + remapped `TradieRates` onto the canonical services. The auto-seed + migration race should be fixed in code.
- `staff@fixo.test` was invited-but-deactivated with no password — completed activation via the MailHog invite token.
- `tradie-verified@fixo.test` had `EmailVerified=false` → login 403 → P1-02 tradie could never pass on a fresh seed.

### Mobile
- `lib/widgets/tradie_widgets.dart` — `const _TradieChip(color: DesignTokens.brand500)` — `brand500` is a computed getter → **const-eval error blocked every iOS build**. Dropped `const`.
- `lib/main.dart` — `await FirebaseMessaging.requestPermission()` before `runApp` held app start behind the iOS system dialog; now `unawaited`. `Firebase.initializeApp` / `GoogleSignIn.initialize` / `getInitialMessage` now bounded so re-running `main()` per test can't hang (`duplicate-app` caught, timeouts added).
- Test harness (`integration_test/helpers/auth_helper.dart`): `pumpAndSettle(kNetworkSettle)` passed 10s as the pump *interval* (timeout default = 10 min) and looping animations (`AbstractOnboardingBackground`, matching spinner) never settle — every test burned 10 min before failing. Replaced all 71 call sites with bounded `pumpFor`. Added `gotoLogin()` which converges to `/auth` from any boot state: first-launch onboarding (Skip), leftover `/verify-email` (`appRouter` is a global singleton that survives `app.main()` re-runs), or a stale dashboard session (clears secure storage + routes to `/auth`). `logout()` now routes to `/settings` directly instead of tapping a nonexistent "Settings" text.
- `integration_test/auth_test.dart` — signup test uses `gotoLogin`.

### New issues from the fourth pass (two-device + fixture run)

8. **`gotoLogin` doesn't converge from non-shell routes (dominant flake)** — after a test leaves the app on `/chat/:id`, `/tradie/jobs/:id`, `/jobs/:id/detail`, or `/jobs/:id/matching`, the next `app.main()` lands there (global `appRouter`), no recognised state matches, `email_field` never appears → `enterText` throws `Bad state: No element`. Caused 8 of this run's failures (homeowner P3-04, tradie P5-04, homeowner P6-06-dismiss, P2-04, P2-09, P4-13-rejected, both P7-04 variants). Fix: treat "no email field + none of the known states" as authenticated-leftover → clear secure storage + `appRouter.go('/auth')`.
9. **Tradie dashboard never surfaces pending offers (product gap)** — `JobRepository.GetForUserAsync` (`backend/Services/JobRepository.cs:32`) returns only `MatchedTradieId == userId` jobs, so a `Pending` offer's job never enters the list; `_IncomingRequestsSection` is permanently empty; the dashboard subscribes to `onNewJobMatch` which `MatchingService` never emits (it emits `OfferLifecycleEvent` to the tradie's user group — only `request_detail_screen` listens). A tradie cannot discover a pending offer without the push notification or an external link. Needs: dashboard subscribe to `onOfferLifecycle` + a jobs query that includes offered-but-unanswered jobs (or a dedicated `GET /api/jobs/offers/pending` list endpoint).
10. **`matching_test` P3-11 navigation cannot reach the matching screen** — tapping a `Requested` card routes to `/chat/:id` via `openHomeownerJob` default branch; `/jobs/:id/matching` is only pushed by the post-job flow. Either route `Requested` → matching screen (if a run is in-flight) or have the test post a job through the app first.
11. **`matching_test` tradie finders use exact text that doesn't exist** — `find.text('Accept')` vs rendered `Review & Accept`/`Accept Job`; `find.text('New Job Request')` vs snackbar `New Job Request: {title}`. Use `textContaining` or the actual copy.
12. **Cross-persona timing budget too tight** — homeowner polls are `kMatchingSettle` = 20 s, but the tradie-side action that would satisfy them sits in a *separate test* that first re-runs `app.main()` + `loginAs` (~50 s worst case). The suites need longer polling, or each persona's steps need to live in one continuous test per persona.
13. **`cancellation_test` P6-06 `findsOneWidget` on `textContaining('fee')`** — the sheet legitimately renders two fee-related strings → matches 2 → fails. Assert `findsWidgets` or scope to the specific string.
14. **`dispute_test` stale finder** — `find.byType(Card)` never matches; the jobs list renders `ModernJobCard` (Container-based). False "No jobs found" skip even with seeded jobs.
15. **Seed script still incomplete for matching** — `tradie-verified` needed manual SQL for: `TradieProfiles` row, `TradieRates` (service 1 @ 85.50), **and an approved `License` credential** (service 1 is licence-gated — `RequiresLicence=true`; without it the profile is excluded even when verified+available). `seed-test-accounts.sh` should create all of this, and the demo `tradie@fixo.nz` profile outranks the test tradie (distance 0 vs ~1.4 km + existing ratings) — the seed should either make tradie-verified the top candidate or the test fixture needs the demo tradie parked.
16. **Job auto-cancel on offer exhaustion is aggressive for tests** — job 61's pending offer expired (10 min default `Matching:OfferWindowMinutes`) → next candidate → none → `Cancelled`/`no_tradie_found`. Correct product behaviour, but a test fixture `Requested` job self-destructs if nobody answers; document or seed with `--keep`-style longer window for manual QA.

## What changed in the harness

- **`helpers/api_helper.dart` extended** — `createJob`, `dispatchMatch`,
  `respondToOffer`, `checkIn`/`checkOut`/`confirmCompletion`, `getPayment`,
  `uploadReceipt` (multipart), `verifyPayment` (staff), `setAvailability`,
  `staffToken`. All HTTP calls now throw on ≥400 instead of silently returning
  error bodies.
- **`helpers/fixture_helper.dart` (new)** — `requestedJob()` →
  `pendingOfferJob()` → `awaitingPaymentJob()` → `paymentReviewJob()` →
  `bookedJob()` → `inProgressJob()` → `awaitingConfirmationJob()` →
  `completedJob()` drive a fresh job through the real API and return its ID.
  `parkCompetingTradies()`/`restoreCompetingTradies()` toggles the demo
  tradie's availability so the test tradie wins sequential matching.

  needs, navigates straight to the route (`appRouter.go/push`), and polls the
  API for backend state instead of polling screen text. No more "See all" +
  `find.text('Requested').first` list-scraping; no dependency on
  p3/p4-smoke ordering. Two-device suites can now run each persona on a
  single simulator.
- `zz_debug_test.dart` deleted; `screenshots_*_test.dart` moved to
  `mobile/screenshot_test/` so `flutter test integration_test/` is functional-
  only; redundant `pumpFor` after `app.main()` removed (~10s × N tests).
- `docs/RUNNING-TESTS.md` updated — render-probe `--page/--fixture` signature,
  build-collision stagger warning, `FIXO_DISABLE_PUSH`, self-seeding docs.

17. **Receipt dedupe rejects identical bytes across payments** —

18. **Dispute evidence upload endpoint mismatch (product bug)** —
    `jobs_repository.dart:435` posts to `/api/disputes/{id}/evidence`, but the

    There is nothing to pop`. Real navigation pushes so it doesn't crash in

    `OfferLifecycleEvent`s. If the offer was created before the screen

21. **`payment_status_screen` has no test Key** — only copy-based finders
    possible ('Payment status' / 'Under review'). Working but brittle; a
