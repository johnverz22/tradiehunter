## Defects found in the fix pass itself (fixed during this run)

1. **`matching_screen.dart` — missing import (compile break).** The A4 fix
   references `JobStatusEvent` without importing
   `repositories/job_hub_client.dart`. `flutter test` failed at
   `kernel_snapshot` for every suite until the import was added.
   → fixed in this session.

2. **`request_detail_screen._respond` — `context.pop()` crash on deep link.**
   Same class as A3, missed in the fix pass: accepting/declining an offer
   via `/tradie/requests/:id` entered with `go()` threw
   `GoError: There is nothing to pop`. Applied the same `canPop()` pattern
   (fallback `context.go('/tradie')`). P3-04 then went green.
   → fixed in this session.

3. **Screenshot drivers must live under `integration_test/`.** The earlier
   move to `mobile/screenshot_test/` made `flutter test` run them
   host-side — no plugin channels, so `Firebase.initializeApp` throws
   `PlatformException(channel-error)` and the app never starts. Moved back
   to `integration_test/`; the run scripts enumerate functional files
   explicitly instead of sweeping the directory.
   → fixed in this session (docs updated).

## Notes / observations

- Tradie dashboard now has a real pending-offer surface: an "Incoming
  Requests" section with per-offer cards (Review & Accept / Decline). The
  request-detail screen loads the job + offer and shows the
  "Respond within mm:ss" countdown.
- Matching screen reaches the "Contacting Tradie N…" state even when the
  offer predates screen entry (the A4 re-read).
- `mk-shot-fixtures.sh` added under `scripts/` — curl-based equivalent of
  `FixtureHelper` for host-side fixture creation (used for screenshots).
- Screenshot driver job IDs are now `--dart-define`s
  (`SHOT_MATCH_JOB`, `SHOT_PAYMENT_JOB`, `SHOT_BOOKED_JOB`,
  `SHOT_INPROGRESS_JOB`, `SHOT_OFFER_JOB`) — no hardcoded IDs.
- The two intentionally-red tradie matching tests from v1.3 are now green;
  their `reason:` comments describing the bug are stale and could be
  cleaned up, but are harmless.
